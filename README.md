# Dhathuru

Door-to-door trip planning and booking for the Maldives. One search plans and books the whole journey (for example ferry, taxi, domestic flight, taxi) and never plans a connection the traveller cannot make.

> Work in progress. Data shown by the app may be estimated or synthetic and is flagged as such. Sea routes are illustrative, never navigational.

## Stack

Next.js 16 (React 19, TypeScript, Tailwind v4) · .NET 10 modular monolith · PostgreSQL + PostGIS · OpenAPI contract in `packages/contracts` · Docker Compose for local infrastructure.

## Repository layout

```
apps/web/            Next.js app
apps/api/            .NET solution (Dhathuru.sln): Api, Domain, Identity, Catalog, Integrations, TripEngine, Bookings, DataTools
packages/contracts/  Split OpenAPI spec, bundled spec and generated TypeScript types
infra/               docker-compose (Postgres + PostGIS, Mailpit) and database init
scripts/             dev-setup.sh, api.sh
brand/               Logo placeholder (drop the final logo.svg here)
```

## Prerequisites

Node 22+ (24 or newer is fine), pnpm 10+, .NET SDK 10, Docker.
If `dotnet` is installed in `~/.dotnet` and is not on your `PATH`, the scripts in `scripts/` find it automatically.

## Run it

```bash
pnpm install
bash scripts/dev-setup.sh   # one time: random local credentials and signing keys (git-ignored / user-secrets)
pnpm dev                    # everything: Postgres + Mailpit, catalog import, .NET API, map tiles, web
```

`pnpm dev` waits for each service and prints `Ready` with the URLs: web http://localhost:3000, API http://localhost:5100 (`/v1/health`), mail UI http://localhost:8025. Ctrl+C stops what it started (Postgres keeps running; `pnpm infra:down` stops it). The web uses the real API (`API_MODE=real`).

No Docker or .NET handy? `pnpm dev:mock` starts the Prism mock API (http://localhost:4010) and the web only (`API_MODE=mock`).

Overrides: `PORT`, `API_PORT`, `TILES_PORT`, `MOCK_PORT`, `Database__Name`. Individual pieces: `pnpm api`, `pnpm mock`, `pnpm dev:web`, `pnpm infra:up`.

## Everyday commands

| Command                 | What it does                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `pnpm lint`             | ESLint for the web app and contract lint                                               |
| `pnpm typecheck`        | TypeScript strict checks                                                               |
| `pnpm test`             | Web unit tests (Vitest) and contract tests                                             |
| `pnpm --filter web e2e` | Playwright smoke tests at 1440 px (needs `pnpm exec playwright install chromium` once) |
| `pnpm api:test`         | .NET tests (xUnit)                                                                     |
| `pnpm api:build`        | Build the whole .NET solution                                                          |
| `pnpm contracts`        | Re-bundle the OpenAPI spec and regenerate types                                        |
| `pnpm infra:down`       | Stop local infrastructure                                                              |

## Configuration and secrets

Nothing secret is committed. Local credentials are generated by `scripts/dev-setup.sh` into `infra/.env` and .NET user-secrets, both git-ignored. See `infra/.env.example` and `apps/web/.env.example` for the variables.

## Contract

`packages/contracts/openapi/*.yaml` is the source of truth for the HTTP API (one file per module, shared schemas in `components/`). The bundled spec and generated types live in `packages/contracts/generated/` and must be regenerated (`pnpm contracts`) when the spec changes.
